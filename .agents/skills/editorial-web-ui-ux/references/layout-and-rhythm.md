# Layout and Rhythm

Use these rules when defining information architecture, editorial grids,
asymmetric composition, whitespace, navigation, heroes, or repeated modules.

## 1. Information architecture

- Identify one primary user goal and one primary page action before selecting a
  layout.
- Group related content into clear sections and order it by user priority.
- Keep top-level navigation limited and labels concise.
- Make the page understandable without animation.
- Avoid repeated information and sections added only to increase page length.
- Keep contact, inquiry, purchase, booking, or project-view actions easy to
  locate.

A useful portfolio sequence is identity, featured work, selected work, about,
capabilities, supporting stories, contact, and footer. Change it when the
actual user journey requires another order.

## 2. Editorial grid

- Establish recurring vertical anchors before introducing asymmetry.
- Prefer 12 columns for wide desktop, 6 for tablet, and 4 for mobile as a
  starting framework, not an inflexible rule.
- Create one dominant visual element in each major viewport.
- Mix large, medium, and small modules instead of equalizing every card or
  image.
- Preserve intentional empty columns when they strengthen composition.
- Use full-width sections sparingly.
- Avoid centering every section or wrapping all content in containers.
- Align selected offsets to a grid line, element edge, baseline, image
  boundary, section transition, or recurring page anchor.

Do not scatter, rotate, overlap, or offset content without a visible structural
relationship.

## 3. Controlled asymmetry

- Build each section around one clear compositional idea.
- Alternate left-aligned, right-aligned, split, narrow, offset, and full-width
  arrangements.
- Avoid repeating the same image/text split more than twice in succession.
- Use scale contrast to distinguish primary and secondary content.
- Crop imagery intentionally instead of fitting every image inside a box.
- Use borders, rules, numbers, coordinates, and labels only when they clarify
  structure.
- Avoid nested panels, generic cards, identical shadows, and uniform corner
  treatments.
- Remove overlap when it damages reading order or responsive stability.

## 4. Page rhythm

Assign every section one density:

- Sparse: one focal element, large whitespace, limited copy
- Balanced: image and text have comparable weight
- Dense: several related elements with strong internal hierarchy
- Immersive: image or media dominates and supporting UI recedes
- Transitional: a short reset using text, numbering, imagery, or whitespace

Follow these rhythm rules:

- Do not use the same density more than twice in succession.
- Do not repeat one layout structure in consecutive sections.
- Follow complex or dense sections with quieter sections.
- Avoid consecutive full-width images or three consecutive text-heavy sections.
- Add a visual reset every two or three sections.
- Vary section height according to content importance.
- Do not alternate background colors mechanically.

## 5. Whitespace and hierarchy

- Use tight spacing inside related groups and larger spacing between topics.
- Keep generous breathing room around display type and hero imagery.
- Use unequal margins only when they strengthen alignment and emphasis.
- Reduce whitespace proportionally on mobile without flattening the rhythm.
- Do not fill empty areas with unnecessary icons, badges, or shapes.

Every major viewport must communicate what to notice first, what to read
second, what action is available, and what information is secondary.

## 6. Navigation, heroes, and modules

- Keep primary navigation visible or easy to access and show current state.
- Avoid hiding essential navigation behind experimental gestures.
- Provide predictable menu controls and clear routes back to an index.
- Use sticky navigation only when it improves access.
- Let the hero communicate identity or purpose with one dominant message or
  visual.
- Avoid combining a large headline, long paragraph, many buttons, badges, and
  several illustrations in one hero.
- Do not make every hero exactly `100vh`; protect important content on smaller
  laptops.
- Keep repeated module structure consistent while allowing selected modules to
  vary in scale.
- Keep actions close to the content they affect.
- Make hover-revealed information available without hover.
